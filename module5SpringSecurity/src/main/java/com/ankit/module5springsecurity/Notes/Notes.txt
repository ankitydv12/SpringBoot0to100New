We can Authenticate user/client with the 3rd party authentication provider like google , facebook , github , linkedin etc.

For the authentication with google we use OAuth2 and we need go create a OAuth Client

Steps
0. Add dependencies
    dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-oauth2-client</artifactId>
    </dependency>
1. Go on the Google Console website
2. Create a Project On Google Console and then select it
3. From the 3Line(Nav Bar) go to the Api and Services -> Credentials
4. From Credentials , Create new Credentials -> OAuth Client ID
5. Complete the process

Imp :
    Authorized JavaScript origins -> add the urls and suburl from where your account make request to the Oauth2
    Authorized redirect URIs      -> In this sections add the url of the your backend system which receive the authenticated token from google
    Testing User -> add google email of the testing user
    User Type -> External
    Scope -> the permission you want like email , name etc . Their are 2 types of scope Non Sensitive and Sensitive
             Add Non Sensitive : email,profie,openid

6. After Successfully Creation copy the Client-id and Client-Secret add to application.properties of aplication.yml
    spring:
      security:
        oauth2:
          client:
            registration:
              google:
                client-id:
                client-secret:

How OAuth2 is used in this project
=======================================================

1. OAuth2 login is enabled inside WebSecurityConfig.java

    .oauth2Login(oauth2LoginConfi ->
            oauth2LoginConfi
                    .failureUrl("/login?error=true")
                    .successHandler(oAuth2SuccessHandler)
    )

Meaning:
    - Spring Security starts OAuth2 login flow for configured provider like Google
    - If login fails, user is redirected to /login?error=true
    - If login succeeds, control goes to OAuth2SuccessHandler instead of default behaviour

2. SecurityFilterChain works with OAuth2 and JWT together

    - /posts, /error, /auth/** and /home.html are public
    - all other endpoints require authentication
    - session policy is STATELESS
    - jwtAuthFilter is added before UsernamePasswordAuthenticationFilter

Concept:
    OAuth2 is used only for initial third-party authentication.
    After successful OAuth2 login, application creates its own JWT-based authentication flow.
    So external login provider verifies identity first, then our backend issues tokens for future requests.

3. Role of OAuth2SuccessHandler.java

    OAuth2SuccessHandler runs after successful OAuth2 authentication.
    It extends SimpleUrlAuthenticationSuccessHandler and overrides:

        onAuthenticationSuccess(HttpServletRequest request,
                                HttpServletResponse response,
                                Authentication authentication)

4. What happens inside OAuth2SuccessHandler

    a. Authentication is cast to OAuth2AuthenticationToken
       This confirms login came from OAuth2 provider.

    b. Logged-in user details are read from DefaultOAuth2User
       Example attributes used here:
           - email
           - name

    c. Application checks local database using email
           User user = userService.findByEmail(email);

       If user does not exist, a new local user is created and saved.

    d. After that application generates its own tokens using JwtService
           String Accesstoken = jwtService.generateAccessToken(user);
           String RefreshToken = jwtService.generateRefereshToken(user);

       This is the key idea:
           Google authenticates the user,
           but our system creates Access Token and Refresh Token for authorization in our APIs.

    e. Refresh token is stored in cookie
           Cookie cookie = new Cookie("RefreshToken", RefreshToken);
           cookie.setHttpOnly(true);
           cookie.setSecure(true);

       Meaning:
           - HttpOnly prevents JavaScript access
           - Secure sends cookie only on HTTPS

    f. User is redirected to frontend with access token
           http://localhost:8080/home.html?token=...

5. End-to-end flow

    User clicks "Login with Google"
        ->
    Spring Security redirects user to Google
        ->
    Google authenticates user
        ->
    Google redirects back to Spring Boot app
        ->
    OAuth2SuccessHandler executes
        ->
    App reads email and name
        ->
    App creates/fetches local user
        ->
    App generates JWT access token + refresh token
        ->
    Refresh token stored in cookie
        ->
    User redirected to frontend with access token

6. Practical understanding

    OAuth2 here is not used for direct session-based login after authentication.
    It is used as a trusted identity provider.

    Final app flow is:
        OAuth2 provider for identity verification
        +
        JWT for stateless API authentication

This combination is common in modern applications because:
    - users can login with Google easily
    - backend does not need to manage Google passwords
    - backend still keeps full control over its own authorization/token system
