============================================================
JWT (JSON Web Token)
============================================================

What is JWT?
-------------
JWT is a compact, signed token used to identify an authenticated user.
It allows the server to authenticate requests without storing a login
session in memory or in a database.

JWT has three parts:

    header.payload.signature

    Header      -> Algorithm and token type
    Payload     -> Claims, such as user id, email, and roles
    Signature   -> Proves that the token was created by the server and
                   has not been changed

Important: JWT payloads are encoded, not encrypted. Do not store passwords
or other sensitive information inside a token.


Login Flow in This Project
--------------------------
1. Client sends email and password to:

       POST /auth/login

2. authController passes the LoginDTO to AuthService.

3. AuthService calls AuthenticationManager.authenticate(...).
   Spring Security checks the email and the BCrypt-encoded password.

4. After successful authentication, AuthService gets the authenticated User.

5. JwtService.generateJwtToken(user) creates and signs a JWT.

6. The token is returned to the client. The client should send it on later
   requests using the Authorization header:

       Authorization: Bearer <jwt-token>


JWT Creation in JwtService
--------------------------
The token currently contains these claims:

    subject  -> User id
    email    -> User email
    Role     -> ADMIN and USER
    iat      -> Issued-at time
    exp      -> Expiration time

The token is signed with the secret configured by:

    spring.jwt.token

The same secret key must be used both to create and to validate tokens.
The current expiration time is one minute:

    System.currentTimeMillis() + 1000 * 60


Reading a JWT
-------------
JwtService.getIdFromJwtToken(token) does the following:

1. Creates the signing key from the configured secret.
2. Verifies the token signature.
3. Checks that the token is valid and not expired.
4. Reads the subject claim.
5. Converts the subject into the user's Long id.

If the token is invalid, modified, or expired, token parsing fails and the
request must be rejected.


Stateless Security
------------------
WebSecurityConfig uses:

    SessionCreationPolicy.STATELESS

This means the server does not store an HTTP session for the user. Every
protected request must contain a valid Bearer token.

The login and signup endpoints are public because `/auth/**` is permitted.
Other protected endpoints must be configured to require authentication and
appropriate roles.


Security Rules
-------------
- Keep the JWT secret outside source control, preferably in an environment
  variable or a protected configuration file.
- Use a sufficiently long, random secret for HMAC signing.
- Never log the JWT or send it in a URL query parameter.
- Use HTTPS so the token cannot be intercepted in transit.
- Keep access tokens short-lived; use refresh tokens if long sessions are
  required.
- Add a JWT authentication filter before protected requests are processed.
  The filter should read the Bearer token, validate it, load the user, and
  place the authenticated user in Spring SecurityContext.


Request Example
---------------
Login:

    POST /auth/login
    Content-Type: application/json

    {
        "email": "user@example.com",
        "password": "password"
    }

Authenticated request:

    GET /post/1
    Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
